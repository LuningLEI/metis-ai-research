# Platform Requirements Worksheet

Use this worksheet to define an evaluation. These are proposed requirements, not a statement that any vendor implements every item.

| Requirement | Why it matters | Evidence to request | Internal owner | Result |
|---|---|---|---|---|
| Collection surface is identified | API and consumer experiences may differ | One labeled answer record | | |
| Question versions are preserved | Wording changes affect comparisons | Version history or equivalent evidence | | |
| Collection failures are separated | Missing data is not brand absence | Failure and refusal examples | | |
| Metrics have explicit denominators | Headline scores can mean different things | Calculation walkthrough | | |
| Answers can be inspected | A chart needs an evidence path | Sample raw or inspectable records | | |
| Claims can be reviewed against sources | Draft quality requires factual support | Reviewer workflow demonstration | | |
| Changes can be followed over time | Publication requires follow-up | History available in the actual plan | | |

Record unknowns explicitly. Distinguish an unavailable capability from a capability that has not yet been demonstrated.

Decision: proceed to pilot / revise scope / do not proceed. Record the rationale and review date.
